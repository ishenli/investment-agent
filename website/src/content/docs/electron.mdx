## 概述

Investment Agent 的 Electron 桌面应用将完整的 Web 功能封装为本地应用，提供以下核心优势：

<CardGrid>
  <Card title="本地数据库" icon="document">
    SQLite 数据库存储在用户目录，数据完全本地可控，支持离线使用。
  </Card>
  <Card title="系统级集成" icon="setting">
    原生通知、托盘图标、Dock 徽章、自动更新等系统级功能。
  </Card>
  <Card title="独立运行" icon="rocket">
    内置 Node.js 服务端，无需额外部署，开箱即用。
  </Card>
  <Card title="安全隔离" icon="approve-check">
    主进程与渲染进程隔离，IPC 安全通信，敏感操作受控执行。
  </Card>
</CardGrid>

## 安装与下载

### 从 Release 下载

仅支持 **macOS** 平台：

1. 访问 [GitHub Releases](https://github.com/ishenli/investment-agent/releases) 
2. 下载 `ig-x.x.x-arm64.dmg`（Apple Silicon）或 `ig-x.x.x-x64.dmg`（Intel）
3. 打开 DMG，将 `ig` 拖入 **Applications** 文件夹
4. 首次启动如遇安全提示，前往 **系统设置 → 隐私与安全性** 点击"仍要打开"

### 目录结构

macOS 上应用数据存储在以下位置：

| 平台 | 数据目录 |
|------|---------|
| macOS | `~/Library/Application Support/ig/` |

<Aside type="tip" title="数据库位置">
  生产环境下 SQLite 数据库位于数据目录下的 `sqlite.db` 文件。升级应用时此文件会自动保留。
</Aside>

## 应用架构

### 进程模型

```
┌─────────────────────────────────────────────┐
│              Electron 主进程                  │
│  (electron/main.ts)                           │
│  • 窗口管理  • 托盘图标  • 自动更新            │
│  • IPC 处理  • 服务端子进程管理               │
├─────────────────────────────────────────────┤
│            UtilityProcess (Node.js)          │
│  (.next/standalone/server.js)                │
│  • Next.js App Router  • SQLite 数据库       │
│  • AI 引擎  • 业务 API                        │
├─────────────────────────────────────────────┤
│           渲染进程 (Chromium)                 │
│  (BrowserWindow)                             │
│  • React 前端界面  • 图表渲染                  │
│  • 通过 IPC 与主进程通信                      │
└─────────────────────────────────────────────┘
```

### 启动流程

<Steps>
1. **主进程启动**：Electron 加载 `dist-electron/main.js`
2. **加载环境变量**：从用户 Shell（`.zshrc`/`.bashrc`）读取环境变量，确保 API Key 等配置可用
3. **启动服务端**：以 UtilityProcess 启动 Next.js standalone 服务端，自动寻找可用端口
4. **打开窗口**：等待服务端就绪后，加载 `http://localhost:{port}`
5. **初始化完成**：窗口显示、Tray 图标创建、自动更新检查
</Steps>

## 开发指南

### 环境要求

- Node.js 18+
- pnpm
- macOS: Xcode Command Line Tools（用于编译原生模块）

### 启动开发模式

```bash
# 同时启动 Web 服务端和 Electron
pnpm electron:dev
```

此命令会：
1. 启动 Next.js 开发服务器（端口 8888）
2. 等待服务就绪后启动 Electron
3. 支持热更新（前端代码修改自动刷新）

### 构建应用

```bash
# 构建 Electron 可执行文件（不打包）
pnpm electron:build

# 构建并打包 macOS 安装包
pnpm electron:build:pack

# 仅打包 macOS（需先执行 build）
pnpm electron:pack:mac
```

构建产物说明：

| 输出目录 | 说明 |
|---------|------|
| `dist-electron/` | Electron 主进程和预加载脚本 |
| `.next/standalone/` | Next.js 独立服务端（用于打包） |
| `release/` | 最终安装包（.dmg） |

### 调试

<CardGrid>

## 核心功能详解

### IPC 通信

主进程与渲染进程通过预加载脚本暴露的安全 API 通信：

```typescript
// 渲染进程调用示例
if (window.electronAPI) {
  // 版本信息
  console.log('Electron:', window.electronAPI.versions.electron);
  
  // 发送原生通知
  window.electronAPI.notification.showNativeNotification({
    title: '投资提醒',
    body: 'AAPL 达到目标价格'
  });
}
```

暴露的 API 包括：

| 命名空间 | 方法 | 说明 |
|---------|------|------|
| `versions` | `electron`, `node`, `chrome` | 运行时版本信息 |
| `updater` | `checkForUpdates()`, `quitAndInstall()` | 自动更新控制 |
| `updater` | `onUpdateAvailable(callback)` | 监听更新事件 |
| `notification` | `showNativeNotification(options)` | 发送系统通知 |
| `notification` | `setBadgeCount(count)` | 设置 Dock 徽章数字 |
| `notification` | `onNotificationClick(callback)` | 监听通知点击 |

### 自动更新

<Aside type="caution" title="仅支持已签名的正式包">
  自动更新功能仅在使用正式签名打包的应用中生效。开发模式或未签名构建不会检查更新。
</Aside>

应用启动后 30 秒首次检查更新，之后每小时自动检查一次：

<Steps>
1. **检测新版本**：对比 GitHub Releases 上的 `latest-mac.yml`
2. **后台下载**：自动下载更新包，期间不影响使用
3. **提示安装**：下载完成后弹出通知，用户可选择立即安装或稍后
4. **安全重启**：安装时保存所有状态，重启后自动恢复
</Steps>

更新配置位于 `electron-builder.yml`：

```yaml
publish:
  - provider: github
    owner: ishenli
    repo: investment-agent
    releaseType: release
```

### 环境变量加载

Electron 从 GUI 启动（Dock/Finder）时，`process.env` 通常不完整。应用会自动执行登录 Shell 读取用户配置：

```bash
# macOS/Linux 下执行
$SHELL -ilc env
```

这确保了：
- API Key（`OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 等）可用
- Node 版本管理器（nvm、fnm）的 PATH 正确
- 自定义环境变量生效

<Aside type="tip">
  建议将 API Key 添加到 `~/.zshrc`，这样从任何位置启动应用都能正确读取。
</Aside>

### 服务端进程管理

Electron 使用 `utilityProcess` 启动独立的 Node.js 服务端：

- **进程隔离**：服务端崩溃不会导致 Electron 主进程退出
- **端口自分配**：自动寻找可用端口（`127.0.0.1:0`），避免冲突
- **优雅退出**：应用关闭时发送信号，服务端有时间保存数据和关闭连接
- **错误恢复**：服务端异常退出时，主进程记录日志并显示用户友好的错误提示

## 打包配置

### electron-builder.yml

```yaml
appId: com.ig.app
productName: ig
directories:
  output: release
files:
  - dist-electron/**/*
  - node_modules/@libsql/**/*
extraResources:
  - from: .next/standalone/
    to: standalone/
```

关键配置说明：

| 配置项 | 说明 |
|--------|------|
| `files` | 打包时包含的文件，排除源码和开发依赖 |
| `extraResources` | 将 Next.js standalone 输出复制到应用资源目录 |
| `asarUnpack` | `@libsql` 模块必须解压，否则会加载失败 |
| `publish` | 自动更新源配置，指向 GitHub Releases |

### 构建脚本

`scripts/build-electron.mjs` 在打包前执行预处理：

1. **生成版本信息**：写入 `public/version.json` 和 `standalone/version.json`
2. **解析符号链接**：将 `.next/standalone/.next/node_modules` 中的 symlink 替换为真实文件（`electron-builder` 不支持打包 symlink）
3. **编译主进程**：使用 esbuild 将 `electron/main.ts` 和 `electron/preload.ts` 打包为 `dist-electron/`

## 常见问题

### macOS 安全提示无法打开

**原因**：应用未经过 Apple 公证（Notarization）。

**解决**：
```bash
# 移除隔离属性
xattr -rd com.apple.quarantine /Applications/ig.app

# 或在 系统设置 → 隐私与安全性 → 安全性 中点击"仍要打开"
```

### 环境变量未生效

**原因**：Electron 从 Dock/Finder 启动时无法读取 Shell 配置文件。

**解决**：
1. 确保 API Key 已添加到 `~/.zshrc`
2. 或使用 `.env` 文件放置在应用数据目录
3. 重启应用使其重新加载环境
